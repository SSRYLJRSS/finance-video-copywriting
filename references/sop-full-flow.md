# SOP 全流程（S0→S6）

> 泛财经短视频文案全流程操作手册。自包含，无需外部文件。

---

## S0：接收主题

### 启动第一件事：确认写作模式（写死，不可跳过）
**项目启动、开始任何工作之前，必须先向用户确认本次用哪种写作模式**：

```
请选择本次写作模式：
1. 精炼模式（默认推荐）——指定一篇参考文案，拆它的框架，保留骨架+取精去粕+约20%创新
2. 创新模式（少用）——凭网感+资料给5个主题选项
```

- 用户选**精炼模式**（默认） → 先让用户给参考文案，拆解其框架模型架构（钩子/骨架/逻辑链/情绪/金句/数据/收束），**骨架不动，换皮换肉，加入约20%创新**（新数据/新案例/新爽点）；**跳过S3主题选项，S2完成后直接进S4大纲**
- 用户选**创新模式** → 正常走S0→S1→S2→S3（给5个选项）
- **用户没说模式，禁止默认开跑**：模式没确认前，不要开始S1分析/S2资料收集

> 模式确认后，整个项目按该模式执行；用户中途可以切换模式，切换时重新确认。
> **实证**：实战复盘：绝大多数项目使用精炼模式，故默认推荐精炼模式。

### 用户输入方式
| 方式 | 处理 |
|------|------|
| 主题+参考文案 | 最理想。先S1分析参考文案 |
| 只给主题 | 先确认方向，自行找参考文案 |
| 给明确方向（"我要的是——XXX开头"） | 直接执行，不搞选项表 |
| 给多篇参考文案 | 全部读取，提取共性 |

### 选题铁律
1. **只写实事，不写旧事**：今天发生的事才写，两周前的热度不碰
2. **多爆点全前置**：一篇文章三个爆点（如价格+人物+对比），开头全部列出
3. **选题四维度**：反差性、共鸣性、数据性、争议性——至少满足两个

### 关键信号识别
| 用户说的 | 意思 |
|----------|------|
| "全部重写" | 从零写，不是扩写 |
| "按我的来" | 严格按用户结构，不重新设计 |
| "不要那么理性，要流量" | 要情绪化，不要分析型 |
| "太深奥了"/"不够爽" | 分析太学术，上打脸素材 |
| "顺便把主题想出来" | 合并S2和S3 |

## S1：分析参考文案

### 输出要求（写死）
- **动手前强制加载**：必读 `style-system.md` + `opening-ending-patterns.md`，确认风格体系在手再分析
- **双输出，顺序写死**：先①对话中输出完整分析内容，再②保存到本地 `项目目录/分析/分析卡.md`
- **停下等确认**：输出后必须停，等用户说"就这样"/"确认"才进S2，禁止直接开始搜资料

### 操作步骤
1. **读取全部参考文案**→提取：选题角度、情绪节奏、核心论点、结构安排、数据使用方式
2. **素材评分**：共鸣度×2 + 情绪强度×1.5 + 反差度×1 + 具体性×0.5 + 传播性×0.5
3. **定位"路"**：对标视频已火=这条路被验证过，复刻逻辑链
4. **明确约束**：主题选项必须与参考文案相同或相近，只微调不偏离

### 素材评分等级
| 等级 | 分数 | 处理 |
|------|------|------|
| S级 | 25-27.5 | 核心素材，必须用 |
| A级 | 20-24 | 优质素材，优先用 |
| B级 | 15-19 | 普通素材，可以用 |
| C级 | 10-14 | 弱素材，尽量不用 |
| D级 | <10 | 淘汰 |

### 核心认知
- 对标视频是"**路**"不是"参考"——已验证流量（5万赞≈播放过百万），逻辑链必须复刻
- 二稿=照着火的稿子**改**，不是推翻重写
- 自由发挥只允许在细节处"添一两句"，改完要能看出"还是那条路"

## S2：资料收集

### Step 1：搜索清单先行
先列≤7个待回答问题（维度/问题/目标来源类型/关键词），防止跑偏。

**8维度搜索策略**：
| 维度 | 搜索关键词模式 | 目标 |
|------|----------------|------|
| 事件与时间线 | "{主题} 事件 时间线 {年份}" | 精确时间点 |
| 核心数据 | "{主题} {人物} 职务 年龄 背景" | 人物背景 |
| 官方回应 | "{机构} 通报 {主题} 处理结果" | 官方态度 |
| 行业背景 | "{机制名称} 案例" | 制度分析 |
| 公众影响 | "{主题} 舆论 反应 微博" | 舆论倾向 |
| 同类案例 | "{类型} 类似事件 处理" | 历史对比 |
| 法律条文 | "{法律名称} {条款} 适用" | 法律依据 |
| 高赞舆论 | "{主题} 知乎 高赞 评论" | 网友观点 |

### Step 2：按主题类型选渠道组合（同时搜2-3个，卡住立刻换）
| 主题类型 | 渠道组合 |
|----------|----------|
| 财经新闻/企业事件 | 通用搜索 + 百度 + 公众号 |
| 社会热点/舆论事件 | 通用搜索 + 知乎 + 微博/B站 |
| 国际政治 | 通用搜索 + 英文搜索 + 百度 |
| 人物故事 | 百度 + 知乎 + 公众号 |

### Step 3：多源交叉验证（关键数字必做）
- 金额/人数/占比/时间点→至少2个独立来源印证（官方+媒体或两家媒体）
- 只1个来源=待核验，不许进大纲
- 冲突保留标注，找第3来源仲裁

### Step 4：素材评分+排事件链+提炼表
- 素材评分表：见S1评分机制
- 事件链：按时间排列，标注每个素材的"链上功能"（钩子/入场场景/异常/反转/规则/代价/机制/收束）
- 覆盖情况表：维度 × 已核验资料 × 关键发现 × 风险

### 资料卡格式
```markdown
# {编号}-{短标题}
- **维度**：
- **结论**：
- **事实**：1. ... 2. ...
- **数据**：
- **来源**：[{媒体标题}]({URL})
- **发布日期**：
- **可信等级**：A(官方/法院) / B(权威媒体) / C(自媒体)
- **可用于**：钩子/事实还原/机制解释/对比/结尾
- **风险**：
```

### 注意事项
1. 不写"来源：知乎/媒体"，必须留URL
2. 不用搜索摘要替代原文阅读
3. 不为凑数量重复同一事实
4. 不把高赞评论写成事实
5. 社交舆论仅用于情绪分析，不用于证明事实

## S3：主题选项

> ⚠️ **仅创新模式走本步骤。精炼模式永远跳过 S3**（用户多次纠正："我是精炼模式，哪来的 s3"）。精炼模式 S2 完成后直接进 S4 写大纲。

### 输出要求（写死）
- **双输出，顺序写死**：先①对话中输出完整5个选项，再②保存到本地 `项目目录/主题选项/主题选项.md`
- **停下等确认**：输出后必须停，等用户选定或给出方向，禁止直接进入S4写大纲

### 双模式（⚠️ 模式在启动时已确认，见S0）
| 模式 | 触发条件 | 操作 |
|------|----------|------|
| **创新模式** | 启动时用户选"创新模式" | 给5个选项：封面+标题+角度+流量点+情绪点 |
| **精炼模式** | 启动时用户选"精炼模式" | **不走本步骤！** S2完成后直接S4；骨架不动，换皮换肉+约20%创新 |

> **模式在项目启动时确认**（见S0"启动第一件事"）。S3只是按已确认的模式执行，不再重新询问。用户中途切换模式时重新确认。

### 核心约束
- 主题选项必须与参考文案**相同或相近**
- 主题=大命题，不细化到具体素材
- 用户给明确方向时不搞选项表，直接设计

### 抓敏感点（找不到敏感点=没重点=没人看）
1. 观众愿意看什么？（不是"我想写什么"）
2. 这件事最扎心的点是什么？
   - 价格 > 参数
   - 不平等 > 政策叙述
   - 外娶 > 生育率数据
3. 多爆点时开头全部前置

### 输出格式
5个选项，每个包含：封面（4-5字关键词+描述）、标题（一句话亮点前置）、角度、流量点、情绪点。用表格对比+推荐排序+理由。

### 选题角度类型（按主题选）
- **市值对比型**：反差最强（如"蜜雪冰城=44个奈雪"）
- **消费降级型**：共鸣最强
- **品控危机型**：冲击力最强
- **反派人设型**：又当又立/监控大师/过河拆桥/伪君子/双重标准
- **人造天才翻车型**：成年人操盘，孩子当工具
- **对比打脸型**：多个案例对比，揭露系统性问题

## S4：写大纲

### 输出要求（写死）
- **动手前强制加载**：必读 `style-system.md` + `opening-ending-patterns.md` + `structure-and-topics.md`，确认风格与结构模板在手再写
- **双输出，顺序写死**：先①对话中输出完整大纲，再②保存到本地 `项目目录/大纲/大纲.md`
- **停下等确认**：输出后必须停，等用户说"就这样"/"开始写"才进S5，禁止直接开始写正文
- **大纲先行**：即使用户说"开始写文章"，也先出大纲等确认

### 前置规则
- **字数由用户指定**，未指定则询问
- 大纲本身必须**口语化写**，不用模板语言/书面语/学术框架
- ❌ "核心判断：不是男女对立，是权利义务的套娃游戏"
- ✅ "你品品，女性挣脱义务叫独立，男性卸下责任叫摆烂。这哪是平权，这是套娃游戏"

### Step 1：搜索高赞回答，提取核心争议点
- 搜索话题关键词，获取高赞回答
- 从中提取**3-5个核心争议点**
- 每个段落聚焦一个争议点，不分散
- 案例（泰山铁丝网）：成本造假→监狱标准围山→生态破坏→防的是逃票→一问三不知

### Step 2：按主题类型选结构模板

| 类型 | 结构 | 适用场景 |
|------|------|----------|
| **时事揭露** | 钩子→事件→机制→正当对比→反噬打脸→定性 | 新闻事件揭露 |
| **清流对比** | 钩子（清流反常操作）→行业乱象→更多善举→情绪定性收束 | 正面人物/品牌 |
| **人物传奇** | 事实罗列→身份揭秘→传奇经历→反噬/代价 | 人物故事 |
| **雪上加霜** | 每段比上段更惨，层层叠加负面 | 社会问题/制度困境 |
| **续集融爽** | 逐篇拆解爽点→选3-4个串主线→标注每段融合哪个爽点 | 爆款续集 |
| **反派人设** | 钩子（新闻事件）→反派形象逐步建立→原因分析→评价收尾 | 企业/产品黑幕 |

### Step 3：大纲核心逻辑教训（10条）
1. **画面先行**比数据先行更有冲击力
2. **人物串联**数据，不要只有数据没有温度
3. **机制穿插**在故事中，不单独成段
4. **反差一次性炸**，不要提前剧透
5. **收束要克制**，参考文案风格
6. **每段只承担一个功能**
7. 逻辑链是"**问-答**"式递进，不是"列清单"式并列
8. 开头要**合并紧凑**：同一维度信息合成一段
9. 过渡要**怼观众**："你觉得大佬在吓唬人？现实数据就摆在这里"
10. **历史规律独立成段**，不当其他段落的附件

### 大纲被退常见原因
| 反馈 | 原因 | 解法 |
|------|------|------|
| 太散 | 没聚焦核心争议 | 搜高赞回答提取3-5个点 |
| 不够吸引人 | 角度太平淡 | 参考高赞回答的角度 |
| 偏离参考文案 | 跑偏了 | 以参考文案为锚点 |
| 节奏慢 | 段落太长/铺垫太多 | 3-5句话一段，爽点前置 |
| 没敏感点 | 写"我想写的" | 先找敏感点，找不到换角度 |
| 拖节奏 | 同一事实翻来覆去 | 同一事实不说第二遍 |

## S5：写文章

### 输出要求（写死）
- **动手前强制加载**：必读 `anti-report-and-ai-flavor.md` + `revision-and-pitfalls.md` + `high-info-density.md`，没加载完不许写正文
- **双输出，顺序写死**：先①对话中输出完整正文，再②保存到本地 `项目目录/文章生成/文章.md`
- **字数用脚本统计**：交付前用脚本统计「中文字数」+「含标点总字符数」双值汇报（**字数口径=含标点**），禁止目测估算
- **停下等确认**：交付后必须停，等用户反馈（改稿/确认/重写），禁止自己进入S6封面标题
- **用户没要求，不主动进入S6**：S6封面标题等用户说"出封面标题"再做

### 写作前必须先说爽点
用爽点公式自检：
```
[谁]的[什么东西]被[谁]用[什么方式]搞没了，最后还[怎么样了]
```
自检：这句话能让观众**愤怒**吗？只是"看热闹"=爽点不对。

### 爽文打脸型策略（核心策略，不是可选项）
让普通人爽，找"装逼打脸"的事。流量公式：**势利眼被打脸**。

**爽点分类（按优先级）**：
①势利眼被打脸 ②装逼打脸 ③反差对比 ④魔幻现实 ⑤真性情 ⑥中国相关 ⑦草台班子

### 写作顺序
1. **首句独立**：第一句话单独一行，冲击力强，不铺垫
2. **钩子后连续2-4个异常**：推进同一事件，不跳到别的案例
3. **逐段填充**：每段至少新增一项（数字/动作/规则/关系/后果）
4. **写结尾**：情绪定性收束，不说教
5. **终检**：通读出声，读不出情绪/爽点=不合格

### 高信息熵与场景链（人物案例必读）
固定顺序：
```
承诺/期待 → 第一次异常 → 尝试解决 → 规则反杀 → 直接代价 → 机制解释 → 宏观回扣
```
- 事件链未走完前，不要过早写"资本压榨、行业黑暗"——这些话只承担解释或收束
- 素材不只按分数筛选：低共鸣素材只要承担流程功能，也要保留
- 过渡由问题触发：每段结尾留观众自然会问的问题，下一段只回答它

### 开头铁律（最重要）
1. **字字千金**：开头两行字每个字有信息量，形容词全删
2. **不让人猜**：第一句把"谁、干了啥、结果如何"说透
3. **不列数据**：先用"事"吸引人，数据放中后段
4. **结果前置**：先写完整因果链
5. **写完回头改开头**：初稿写完后必须回头问"观众最感兴趣的点放进开头了吗"
6. **全景扫描不做碎片拼接**：一句话把所有炸点串起来甩出来

**开头公式**：定性 + 惩罚链 + 互动
```
第一句：直接抛定性/冲突（"丢脸丢到国外了"）
中间：一连串具体惩罚/后果——至少3个
收尾：互动句（"你敢信吗？"）
```

**开头三种模式**：
- **数据冲击型**：直接上冲击数据，先给一巴掌再讲故事
- **金句/冲突型**：第一句就抛核心观点/冲突
- **画面感型**：直接进入具体场景

**错误开头（避雷）**：从背景介绍开始、从人物介绍开始、"这不是小说""这不是做梦"

### 结尾铁律
1. **点名对手恐惧**，不解释意义
2. **不总结**：观众已形成判断，总结段=冒犯
3. **短句能独立传播**：短到能截图传播的句子才是好结尾

**结尾正确做法**：
| 类型 | 公式 | 范例 |
|------|------|------|
| 情绪定性 | 情绪词收尾 | "在中国耍横的资本，你没了" |
| 报应/活该 | 因果收尾 | "这叫自作自受" |
| 讽刺 | 反讽收尾 | "好日子到头了" |
| 反差 | 滤镜碎裂收尾 | "滤镜碎了一地，钱包捂得更紧" |
| 反讽金句 | 金句收束 | "当道理讲不通的时候，愤怒就是唯一的通行证" |

**禁止**："普通人应该...""我们应该...""警示""建议""给大家提个醒"、硬上价值

### 生成硬约束
| 要求 | 标准 |
|------|------|
| 个人判断 | ≥3次「要博主我说」/「说白了」/「说到底」，结尾必须用「要博主我说」收束 |
| 口语化 | 每2-3行至少一个口语/互动/吐槽 |
| `<u>`标签 | 只在大纲阶段用（标注有传播价值的句子），最终文章不保留 |
| 段落间距 | 主要段落间不空行，重要转折处可加空行 |
| 信息增量 | 每段至少新增一项（数字/动作/规则/关系/后果），优先新增两项 |
| 吐槽句 | ≥6处，分布均匀（开头1+中间3-4+结尾1-2） |
| 路标词 | ≤2（"雪上加霜的是""更让人寒心的是"每多一处观众多划走一截） |
| 判断变体 | ≥3种（变换"要博主我说/说白了/说到底/博主我觉得"） |
| 数据 | 准确，每个数字有来源，新旧比8:2（新数据为主） |

### 金句铁律
1. **金句是平凡文字表达强烈情感**，不是工整对仗
   - ✅ "剩余的工资被狗吃了吗？" ✅ "这tm不是在工作，这是在挑战人类的生理极限！"
   - ❌ "财报好看了，工人的命却贱了" ❌ "车企的小算盘，打得比流水线还精"
2. **金句只出现一次**：放在最有冲击力的位置，重复=机器人感
3. **金句要具体、有画面感**，不要抽象概念
4. **不硬凹金句做转折**：每段结尾硬塞一句=像完成任务
5. **个人判断变体要多样**

**强凹金句黑名单**：工整对仗型、打脸口号型、说教反问型、鸡汤升华型、同义反复型、过渡硬凹型

### 去AI味流程（写完必过）
1. **`<u>`下划线**在最终文章中全部删除
2. **书面腔改口语**："系统性溃败"→"整个系统在塌"
3. **路标词全文≤2**
4. **空泛归因改具体**："资本是趋利避害的"→"投入和产出倒挂到这份上"
5. **抽象概括改细节**："加班更是地狱模式"→"排队打饭就要10多分钟，来回路程再10多分钟"

**AI味检查清单**：
- [ ] 太工整太对称？（每段结构一样/字数差不多/转折词位置固定→真人不会这样）
- [ ] 转折太生硬？（用反问过渡："你猜老美拿它干嘛？"）
- [ ] 吐槽太刻意？（先铺垫，情绪最高点爆发）
- [ ] 缺个人化表达？（加入具体人名、具体场景）
- [ ] 报告式语言？（"数据显示""研究表明"→全改口语）

### 报告式 vs 文章式（防写成报告）
| 维度 | ❌ 报告式 | ✅ 文章式 |
|------|---------|---------|
| 结构 | 1.现象 2.原因 3.影响 4.建议 | 钩子→冲突→高潮→收束 |
| 语言 | "数据显示""研究表明" | "你品品""好家伙""这谁扛得住" |
| 情绪 | 全程中立客观 | 震惊→愤怒→共鸣→反思 |
| 结尾 | "综上所述""建议" | "散会""评论区见" |

### 立场体系：普通人嘴替（不是财经科普员）
**核心立场：站在"务实普通人"的视角**，解构宏观事件对个体利益（钱、时间、尊严、安全）的影响。

| 维度 | ❌ 科普员（错误） | ✅ 普通人嘴替（正确） |
|------|-------------------|----------------------|
| 立场 | 客观分析事件 | 替观众骂、替观众爽 |
| 数字 | 精确到个位 | 大数模糊化（"200多亿"），政策节点仍精确 |
| 过渡 | "把时间线一摆就明白了" | "把时间线一摆，狐狸尾巴就露出来了" |
| 称呼 | "高净值人群" | "你们这些资本家" |
| 收束 | 抽象升华 | 落到普通人得利+反问收尾 |

**嘴替工具箱**：
- 夸着骂："声明写得那叫一个艺术啊"
- 抓贼感过渡："狐狸尾巴就露出来了"
- 互动反问："你气不气""你品品""天下哪有这种好事？"
- 接地气比喻："藏了多少私房钱""免费保险箱"
- 拍手叫好："国家这波干得是真漂亮！"（独立成句）

### 终检清单
**写作前**：
- [ ] 选题有反差性/共鸣性/数据性/争议性？
- [ ] 角度站在普通人视角？
- [ ] 大纲字数=用户指定字数？
- [ ] 每段一个功能、逻辑链"问-答"式递进？

**写作后**：
- [ ] 字数达标（**含标点口径**）；"博主我"写全（不是"博我"）
- [ ] 吐槽句≥6个且均匀分布
- [ ] 路标词≤2
- [ ] 无独立成段"算账/分析"；无空洞修辞
- [ ] 开头无"这不是小说/不是做梦"；结尾无"应该/建议/警示"
- [ ] 去AI味审计通过
- [ ] 写完自己通读出声，读不出情绪/爽点=不合格

## S5.5：对标文案学习（可选，用户触发）

> **触发**：用户说"这是对标文案，感觉表达比你好""你在学一学"或直接贴对标文案时进入。实证：用户主动喂对标文案让 AI 学表达。

### 操作步骤
1. **拆表达技巧**：逐句拆对标文案好在哪——设问勾互动（"六十万对一个农村家庭是啥概念？"）、慢镜头画面（"井水不深，只没过胸口"）、犀利互动句、情绪节奏
2. **学表达，不学立场**：只学壳（句式/画面/节奏），立场仍按项目定稿，不照搬对标观点
3. **重写**：把学到的表达技巧融入当前稿，重写交付
4. **停下等确认**：重写后停，等用户反馈

## S6：封面+标题

### 输出要求（写死）
- **触发**：等用户说"出封面标题"才做，不主动进入
- **双输出，顺序写死**：先①对话中输出完整选项，再②保存到本地 `项目目录/封面标题/封面标题.md`
- **停下等确认**：输出后必须停，等用户选定或修改，整个流程才算收尾

### 封面（5个选项）
- **4-5字冲突关键词**+一句描述
- 要有情绪冲突，直接说事实
- 不用比喻/抽象概念/对仗句式
- ✅ "德国铁娘子，手撕欧盟政客"
- ❌ "骂遍欧洲，真性情"（太抽象）

### 标题（5个选项）
- **一句话亮点前置**，直接上数据或反差
- 要有具体行为+反差+悬念
- ✅ "骂冯德莱恩是美国走狗，支持率却一路狂飙！德国魏大姐到底在疯什么？"
- ❌ "从冯德莱恩到默茨，就没有她不敢骂的"（太平淡）

| 类型 | 模板 |

| 盗版大佬 | 偷了XXX，还装受害者 |
| 监控大师 | XXX监控你，还说为你好 |
| 过河拆桥 | 用你的数据长大，转身就封你 |
| 伪君子 | 嘴上说XXX，背后全是算计 |
| 双重标准 | 别人XXX叫偷，自己XXX叫优化 |

## 迭代修改

### 用户修改后必须做的事
1. **主动对比差异**：逐段找差距，分析"哪被改了、为什么改、改后好在哪"
2. **总结规律**：把规律写入记忆，下次直接应用
3. **不只说"满意吗"**：要分析用户修改的原因

### 用户改稿六维规律
| 维度 | ❌ 初稿常见问题 | ✅ 用户改稿特点 |
|------|---------------|---------------|
| 封面标题 | 封面抽象/标题平淡 | 封面用具体形象+动作；标题有具体行为+反差+悬念 |
| 开头 | 直接陈述 | 感叹词+具体范围，更有冲击力 |
| 细节描写 | 干巴巴陈述 | 用具体画面+比喻+夸张 |
| 逻辑结构 | 逻辑跳跃 | 从人物背景→社会矛盾→机制解释→情绪收束，层层递进 |
| 口语化 | 机械插入 | 更自然，用具体生活场景+排比句式 |
| 结尾 | 平淡陈述 | 金句收束，反讽有力 |

### 底层差异
用户文本像**一个人在讲故事**，初稿像**AI在堆砌信息**：
- 用户每句话有明确逻辑关系（因果/递进/转折），初稿句子之间无关联
- 用户加入个人反应（"把我都看感动了""好家伙！"）
- 用户过渡自然流畅（"为啥子嘞？""你想想"）
- 用户引用具体素材，初稿泛泛描述

### 关键铁律
- **用户提供的改写版本就是定稿**：只在基础上扩展字数，不改结构、不加用户没有的内容
- "根据我这个略微改过的文本，重新写" = 严格按照用户版本
- "锐评下自己" = 对你的版本不满意，要你学习他的版本

## S7：自我学习

### 触发时机
S6封面标题交付后自动进入。S7是可选步骤——如果用户没有修改版，跳过即可。

### Step 1：读取已有经验
读取 `learnings.md`（与SKILL.md同目录），快速浏览当前积累的经验条目。

### Step 2：向用户索取修改版
输出以下提示：

> "文章交付了。如果你后续手动改过了，请把**完整修改版**发给我——**标题、封面、正文**三个部分都算（改过标题就发新标题，改过封面就发新封面，改过正文就发新正文），我会逐段对比差异，提取通用经验写进经验库，下次写得更接近你的要求。"

**用户可能的回应**：
| 用户说的 | 处理 |
|----------|------|
| 发来了修改版文本 | 进入Step 3 |
| "没改" / "不用了" | S7结束，整个流程完成 |
| "下次再说" | S7结束，下次有修改版再来 |

### Step 3：逐段对比差异
拿到用户的**完整修改版**后（**标题+封面+正文**三个部分，用户改过哪里就对比哪里），和AI的初稿**逐段对比**：

1. **逐段对齐**：按段落顺序，找出用户改了哪些段、哪些句子
2. **分类差异**：
   - 📝 **删减类**：用户删了什么？（删掉的往往是AI多余的）
   - ➕ **新增类**：用户加了什么？（加的往往是AI缺失的）
   - 🔄 **改写类**：用户怎么改的？（同义换皮/换结构/换语气）
   - 📊 **数据类**：用户改了数字吗？（可能AI的数据不准）
   - 🎯 **立场类**：用户的语气/态度和AI有什么不同？
3. **输出对比表**给用户看：

```markdown
## 改稿对比分析

| 段落 | AI初稿 | 用户修改 | 差异类型 | 通用规律 |
|------|--------|----------|----------|----------|
| 第2段 | "数据显示…" | "你品品这数据…" | 语言 | AI用了报告式语言 |
| 第5段 | 293亿 | "200多亿" | 数字 | 大数应模糊化 |
| 第8段 | （整段被删） | - | 删减 | 人设补充段与主题无关 |
```

### Step 4：提取通用经验
从对比表中提取**通用规律**（不是个例）：

**判断标准**：
- ✅ 通用规律："AI倾向于用精确数字，但用户偏好大数模糊化" → 可写入
- ❌ 个例："这篇文章的293亿应该改成200多亿" → 不写入（这是案例不是规律）
- ✅ 通用规律："AI写的过渡句'那问题来了'太客气，用户改为'你觉得大佬在吓唬人？'更有对抗感" → 可写入
- ❌ 已有规则："结尾不要说教" → 不写入（SKILL.md已有）

**每条经验格式**：
```markdown
[日期] [项目类型] [维度: 开头/结尾/结构/语言/立场/数据/流程]
- 观察：AI初稿和用户修改版之间发现了什么差异
- 规律：这个差异背后的通用规律
- 行动：下次写作时应该怎么做
- 置信度：高/中/低
```

### Step 5：输出经验条目给用户确认
将提取的经验条目展示给用户：

> "我从你的修改版中提取了X条通用经验：
> 1. [经验1摘要]
> 2. [经验2摘要]
> 要写入经验库吗？你可以说"全写入"、"只写入第X条"、或"都不写"。"

### Step 6：写入 learnings.md
用户确认后，将经验条目写入 `learnings.md` 对应的置信度区域：
- 高置信度区：验证3次以上的经验
- 中置信度区：验证1-2次的经验
- 低置信度区：仅1次的经验（30天内未升级则删除）

**写入前检查**：
1. 与SKILL.md现有规则重复？→ 不写入
2. 与核心风格规则冲突？→ 标记"需讨论"，不直接写入
3. 是否具体可执行？→ 模糊的改写或删除
4. 是否是个例而非规律？→ 不写入

### Step 7：检查压缩条件
写入后检查 learnings.md 文件大小和条目数：

```
文件大小 > 5KB 或 条目数 > 30 → 执行压缩
```

### 压缩流程

**1. 分类评估每条经验**：
| 状态 | 处理 |
|------|------|
| 低置信度 + 30天内未升级 | 删除 |
| 高置信度 + 已被SKILL.md吸收 | 从learnings.md删除（已在主文件） |
| 重复经验 | 合并为一条 |
| 模糊经验（无法转化为具体行动） | 改写或删除 |
| 仍然有效且未被吸收 | 保留 |

**2. 输出压缩报告**：
```markdown
## 经验库压缩报告
- 压缩日期：2026-XX-XX
- 压缩前：XX条，XXKB
- 压缩后：XX条，XXKB
- 删除了：[列表+原因]
- 合并了：[列表]
- 保留了：[列表]
```

**3. 更新统计表**：在 learnings.md 末尾更新条目数/大小/压缩日期

### 防偏移保障

1. **物理隔离**：learnings.md 独立于 SKILL.md，经验不直接改主文件
2. **写入前检查**：与核心规则冲突→标记"需讨论"不写入
3. **用户审批**：所有经验写入前必须经用户确认
4. **定期压缩**：超阈值自动触发，有规则地删减
5. **维度标注**：每条经验标维度，防止"跨界"影响其他维度
6. **置信度分级**：低置信度的自动过期，不会长期占位

**目标文件对照表**：

## 经验升级方案

以下 N 条高置信度经验已验证多次，建议升级到正式文件：

是否全部升级？你可以说"全部升级"、"只升级第X条"、或"先不升级"。

2. 从 learnings.md 中删除已升级的条目
3. 在 learnings.md 的"压缩日志"记录：升级了什么、升级到哪

### 模式B：文风变更（用户主动改规则）

**触发信号**：
- 用户说"以后不要用东北话了"
- 用户说"以后立场不要那么激进了"
- 用户说"以后结尾要升华，不要直接骂"
- 用户连续多次修改同一个方向（learnings.md里出现与现有规则系统性矛盾的经验）

#### Step 1：定位现有规则
AI在整个skill目录中搜索与用户变更方向相关的规则。

```
搜索关键词 → 定位到哪些文件的哪些段落
例："以后不要东北话" → 
  style-system.md LXX: "东北味注入"段落
  SKILL.md LXX: "高频口语词"段落
  anti-report-and-ai-flavor.md LXX: "口语化替换表"
```

#### Step 2：输出变更方案

```markdown
## 文风变更方案

你要求：以后不要用东北话了

以下是需要修改的地方：

| 文件 | 位置 | 旧规则 | 新规则 |
|------|------|--------|--------|
| style-system.md | 3.4 东北味注入 | 大量使用"贼拉、杠杠的、扯犊子" | 删除此段落，改为通用口语 |
| SKILL.md | 高频口语词表 | "掰扯掰扯、唠唠、好一个" | 改为通用口语词 |
| anti-report-and-ai-flavor.md | 口语化替换表 | 含东北方言 | 替换为通用口语 |

- [经验1] → 建议删除（与新方向冲突）

```

#### Step 3：执行变更
用户确认后：
1. 用 patch 工具逐文件修改
2. 清理 learnings.md 中与新规则冲突的经验
3. 在 learnings.md 的"变更日志"记录变更内容

#### Step 4：记录变更日志
在 learnings.md 末尾的"压缩日志"区域追加：
```markdown
### 变更记录
- [日期] 用户要求：[变更内容]
- 修改了：[文件列表]
- 清理了learnings.md中N条冲突经验
- 影响：[哪些方面会变化]
```

### 防偏移保障（S8专属）

1. **所有升级/变更必须用户审批**——AI不擅自改references文件
2. **矛盾经验不直接升级**——转入模式B让用户决策
3. **变更后清理关联经验**——防止learnings.md里的老经验拉扯新方向
4. **变更日志可追溯**——learnings.md记录每次变更，方便回溯
5. **升级后从learnings.md删除**——避免"正式区+暂存区双重存在"导致冗余
